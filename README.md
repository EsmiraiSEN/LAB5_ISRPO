## Ответы на вопросы
1. **Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?**  
   `int.Parse()` генерирует исключение (ошибку) и обрушивает программу, если строка содержит буквы или пуста. `int.TryParse()` возвращает `false` в случае неудачи, не прерывая работу программы. `Parse` можно использовать, если мы на 100% уверены в валидности данных, во всех остальных случаях (особенно пользовательский ввод) следует применять `TryParse`.
2. **Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.**  
   `switch` удобнее, когда одна переменная сравнивается на равенство с множеством фиксированных значений (констант). Пример из жизни: обработка нажатия клавиш в игре (W, A, S, D) или выбор пункта в текстовом меню банкомата.
3. **Что произойдёт в switch, если убрать break после одного из case?**  
   В C# возникнет ошибка компиляции (за исключением пустых `case`, идущих друг за другом для группировки). Язык запрещает сквозное выполнение ("fall-through"), если в `case` есть код.
4. **Чем отличается = от == в C#? Почему это частая ошибка?**  
   Одиночный знак `=` — это оператор присваивания значения переменной. Двойной знак `==` — это оператор сравнения на равенство. Новички путают их из-за математической привычки, ошибочно пытаясь сравнивать через один знак `=`.
5. **Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**  
   Да, можно. Пример из шага 5: `string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`. Читаемость такого кода резко падает при увеличении вложенности. Использовать вложенные тернарные операторы стоит аккуратно и лишь для очень простых условий.
